# Art assets

Brand assets for PHPRegex. Every asset is generated by one script,
`art/brand.py`, from one geometry and one set of tokens: SVG first, the PNG
and ICO renditions rendered from it. Do not edit an asset by hand — change
the script and run it again.

## The mark

A three-node tree — the AST — between the two slashes that delimit a PHP
pattern: `/…/`. The slashes say "a regex, in PHP" before anything is read;
the tree says what the library does with it.

- **Construction** (in a box centred on 0,0): slashes from (±112…±176,
  ±126), leaning 14° — the slant of a slash in Inter; root node at (0, −64),
  children at (±52, 72). Ink extent ±193 × ±143, a 4:3 box.
- **Two weights.** *Regular* (slash 34, edge 24, root r40, children r32) for
  48 px and up; *bold* (44 / 30 / r44 / r36) for the favicon and every icon
  that renders at 16–32 px, where a 24-unit edge would fall under a pixel.
- **Colour.** Slashes and edges in the ink; the nodes in the accent,
  a diagonal gradient. The hierarchy is carried by shape and size, never by
  hue alone.

## The wordmark

"PHPRegex" in Inter Display SemiBold, tracking −0.02 em, set as paths
shaped by HarfBuzz (real advances and kerning). "PHP" in the soft ink,
"Regex" in the ink: the subject of the name is the regex. In a lockup the
mark is 1.35 cap heights tall, centred on the cap height, 0.40 em from the
word.

Contrast is measured against the ground (WCAG 2.2): text ≥ 4.5:1, graphics
≥ 3:1. The same tokens drive the documentation site (`docs/_sass/`), so the
site and its assets never drift apart.

Theming is explicit files, never `@media` inside a file: every themed asset
ships a light and a dark file, and a README picks one with `<picture>`.

## A card for every page

`art/og.py` writes one Open Graph image per page of the site under
`docs/assets/og/`, at the page's path (`/guides/cli/` →
`docs/assets/og/guides/cli.jpg`): 1200×630, the page's title and
description, an eyebrow naming its section, the section's hue in the glow
(Learn orange, Tutorial green, Integrations sky, Concepts violet, Reference
teal, Internals amber, Articles pink, Findings red), the chapter's number
on a tutorial page and the mark elsewhere, and the page's address. A link
shared on WhatsApp, X, LinkedIn or Slack shows what it leads to.

The page list is read from the built site, so every page is covered —
documentation, tutorial, articles, and the findings of every project —
with no list to maintain. `docs/_includes/head.html` serves the page's card
when the file exists and falls back to the page's own `image`, then to the
site card, so a page added since the last run never shows a broken image.
The home page keeps the site card (`social-dark`). Run it after adding or
retitling pages:

```console
$ (cd docs && bundle exec jekyll build)
$ python3 art/og.py --site docs/_site \
    --inter-display /path/to/inter/extras/otf \
    --mono docs/assets/fonts/jetbrains-mono-var.woff2
```

The cards are JPEG at quality 85 with full chroma, about 50 KB each: the
glows stay smooth, which a palette PNG bands. The output is deterministic,
so a run that changes no page rewrites no file.

## Site copies

The script also writes the documentation site's copies: `docs/favicon.svg`,
`docs/favicon.png`, `docs/favicon.ico` (16/32/48), `docs/apple-touch-icon.png`
(180), `docs/icon-192.png`, `docs/icon-512.png`, `docs/icon-maskable-512.png`
(listed in `docs/site.webmanifest`), and the Open Graph cards
`docs/assets/img/social.png` (the dark card) and
`docs/assets/img/findings-social.png`. The mark itself is inlined in
`docs/_includes/header.html`, `footer.html` and `docs/404.html`, themed by
CSS; a geometry change updates those three in the same commit.

## Regenerating

```console
$ pip install fonttools uharfbuzz brotli
$ python3 art/brand.py \
    --inter-display /path/to/inter/extras/otf \
    --mono docs/assets/fonts/jetbrains-mono-var.woff2
```

`--inter-display` is a directory holding `InterDisplay-Regular.otf`,
`-SemiBold.otf` (from https://github.com/rsms/inter/releases). With
`rsvg-convert` and ImageMagick on the PATH the PNG and ICO files are
rendered too; `--no-render` writes the SVGs only.

## Rules

- **No text glyphs in brand files.** Every word is a path; a file renders
  the same in every viewer, with no font installed.
- **Version ratchet.** Any change to an image served by URL bumps its `?v=N`
  in the README that serves it, in the same commit — a changed image under
  a stale version is invisible to returning visitors (GitHub's camo cache).
- **Accessibility.** Every SVG carries `role="img"` and a `<title>`.
- **Icon floors.** The favicon is checked at 16 px and the org icon at
  20 px before an icon change ships: every node must read against its tile.
